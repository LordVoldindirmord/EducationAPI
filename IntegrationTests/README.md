# Интеграционные HTTP-тесты

Тесты запускают настоящее приложение EducationAPI через WebApplicationFactory и отправляют запросы HttpClient. Проверяются все 18 действий контроллеров: маршрут и HTTP-метод, JSON и multipart, обязательное тело запроса, формат ApiResponse, основные коды ответа, политики доступа и cookie входа/выхода. Подробные ветви бизнес-логики сервисов остаются для unit-тестов.

Для запуска нужен .NET 10 SDK и PostgreSQL с разрешением создавать базы. Команда из папки Backend: `dotnet test IntegrationTests/IntegrationTests.csproj`.

Параметры PostgreSQL можно задать переменной окружения `EDUCATION_TEST_POSTGRES`, например `Host=localhost;Port=5432;Username=postgres;Password=...`. Без переменной используются параметры прежнего тестового окружения: localhost:5432, postgres, пароль 1234. Имя базы из переменной игнорируется. Каждый запуск создает отдельную базу `education_it_<guid>`, применяет миграции приложения и удаляет только эту базу по завершении. Приложение получает отдельное подключение, что дополнительно проверяется тестовым хостом.

Identity, авторизация, сервисы и репозитории работают как в приложении. Вместо SMTP и ЮKassa используются локальные подмены: письма не отправляются, реальные платежи не создаются. Ключи защиты cookie существуют только в памяти тестового хоста. Подготовка пользователей с повышенной ролью и получение созданных идентификаторов выполняются через отдельные DI-scopes, поскольку публичных API для этих операций нет.

Для обложек используется настоящий файловый менеджер с отдельной папкой `%TEMP%/education-http-tests/<guid>` на тестовый хост. Тесты не обращаются к рабочему хранилищу. Автоматической очистки оставшихся файлов нет; тест удаления курса выполняет обычное удаление своей тестовой обложки через эндпоинт.

При добавлении нового действия контроллера тест EndpointInventory сообщит, что перечень HTTP-контрактов нужно дополнить. Новый эндпоинт также требует отдельной проверки успешного запроса.

Для сохранения отчета: `dotnet test IntegrationTests/IntegrationTests.csproj --logger "trx;LogFileName=integration.trx"`. Отчет сохраняется в IntegrationTests/TestResults.
